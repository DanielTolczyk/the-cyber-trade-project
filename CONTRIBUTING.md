# Contributing to The Cybersecurity Trade Project

Thank you for your interest in contributing. This initiative is structured like an open-source standard to build an accountable, accessible cybersecurity trade.

---

## Guiding Principles for Contributions
1. **Practicality Over Pedantry:** Proposals should reflect real-world operational workflows, enterprise realities, and proven skilled trade mechanics.
2. **Accessible Upward Mobility:** Avoid gatekeeping mechanisms that enforce wealth or arbitrary pedigree barriers. Preserve rigor through verified hands-on hours and competency milestones.
3. **Evidence-Based Policy:** Reference existing standards (NIST NICE Framework, DOL Registered Apprenticeship guidelines, state licensing compacts) where applicable.

---

## How to Propose Changes

### 1. Framework Proposals
* **Minor Revisions / Typos:** Open a direct Pull Request with a clear description of the refinement.
* **Structural Amendments:** (e.g., altering apprentice wage percentages, modifying domain rotation hours, or introducing new specialty endorsements)
  * Open an **Issue** tagged `proposal` to discuss the change with the community.
  * Provide an operational justification and impact assessment.

### 2. File Organization
* Pillar updates belong in `pillars/`.
* Quantitative standards (ratios, pay formulas, logbook fields) belong in `framework/`.
* Legal, governance, and board mechanics belong in `governance/`.

---

## Style Guidelines
* Write in a direct, clear, professional voice.
* Use Markdown formatting (tables for metrics, lists for sequential requirements).
* Avoid marketing buzzwords and vendor-specific jargon.
